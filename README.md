# Баннер-бот Seraphic Aurora

**Живые счётчики участников и войса прямо на баннере Discord-сервера.**
Обновляется сам каждые 10 минут. Вмешательство не требуется.

## Как это устроено

Бот не висит в памяти постоянно. Раз в 10 минут его будят, он считает статистику,
перерисовывает баннер и выключается — секунды работы вместо круглосуточного процесса.

```
cron-job.org ──каждые 10 минут──► GitHub Actions ──► once.js ──► баннер сервера
                                        │
                                        ├──► карточка состояния в Discord
                                        └──► пинг сторожу healthchecks.io
```

> [!NOTE]
> **Почему будильник внешний.** Расписание внутри GitHub (`cron` в `banner.yml`)
> для этого аккаунта не срабатывает — ни разу за несколько часов при полностью верных
> настройках. Аккаунт под торговыми ограничениями GitHub, и это, вероятно, задевает
> не только приватные репозитории. Файл расписания оставлен как запасной: если у GitHub
> однажды заработает, лишних заливок не будет — их режут кулдаун и потолок.

## Куда смотреть, если что-то не так

| Место | Что показывает | Признак проблемы |
|---|---|---|
| **Карточка в Discord** | время последней проверки | время застыло больше чем на полчаса |
| **Почта** | письмо от healthchecks.io | пришло письмо — бот молчит |
| **Вкладка Actions** | зелёная галочка или красный крестик | крестик, внутри написано почему |
| **cron-job.org** | код ответа GitHub | не `204` — будильник не достучался |

Карточка — самое быстрое: одно поле, одно число, никакого кода.

## Настройка внешнего вида

<img src="assets/showcase.png" alt="" width="380" align="right">

1. Открыть [страницу настройки](https://zelonka228.github.io/seraphic-counters/)
2. Покрутить ползунки, глядя на имитацию Discord
3. Нажать **«Скопировать настройки»**
4. Вставить блок в `config.json` вместо `banner.badges` и `banner.style`
5. Запушить — обновится в течение 10 минут

Правку оформления бот замечает даже при неизменных цифрах:
в отпечаток входит и стиль тоже.

<br clear="right">

<details>
<summary><b>Все поля конфигурации</b></summary>

<br>

| Поле | Что делает |
|---|---|
| `badges[].counter` | что показывать: `members`, `online`, `voice`, `boosts` |
| `badges[].icon` | иконка: `mic`, `users`, `boost` |
| `badges[].prefix` | текст перед числом, например `"Онлайн: "` |
| `badges[].locale` | `"none"` → `1409`, `"ru-RU"` → `1 409` |
| `style.direction` | `column` — в столбик, `row` — в линию |
| `style.x` / `style.y` | левый верхний угол первой плашки, холст 960×540 |
| `style.fontSize` / `gap` / `radius` | размер шрифта, промежуток, скругление |
| `style.background` / `text` / `border` | цвета плашки, цифр и обводки |
| `style.opacity` / `shadow` | плотность заливки и тени, 0–1 |
| `voice.excludeBots` | не считать ботов, сидящих в войсе |
| `voice.excludeAfk` | не считать ушедших в AFK-канал |

Подложка — `assets/banner-base.png`, размер 960×540.
Шрифт цифр — `assets/font.ttf`, вложен в репозиторий: без него рендер
на Linux выглядел бы иначе, чем на Windows.

</details>

## Команды

```bash
npm test         # проверка рендера и логики, без подключения к Discord
npm run check    # подключиться, показать права и живые цифры, ничего не менять
npm run preview  # нарисовать preview.png с выдуманными цифрами
npm run banner   # постоянный процесс, для своей машины под pm2
npm start        # второй режим: счётчики в названиях каналов
```

Отправить сообщение через вебхук вручную:

```bash
node alert.js "Заголовок" "Текст" success
```

Цвета: `success` зелёный · `info` синий · `warn` жёлтый · `error` красный.
То же самое кнопкой — прогон **«Отправить сообщение»** на вкладке Actions.

## Лимиты Discord

Четыре независимых рубежа, чтобы никогда в них не упереться:

**1. Цифры не изменились — запроса нет вообще.** Ночью бот молчит часами.

**2. Кулдаун 9 минут.** Меньше интервала будильника специально: при совпадении
каждый второй запуск отказывал бы и баннер отставал бы вдвое.

**3. Потолок 8 заливок в час.** Жёсткий, по журналу в `.state.json`, переживает
перезапуск. Выше частоты будильника, чтобы не резать законные обновления.

**4. Сигнал самого Discord.** Если он придержит запрос, бот возьмёт названное
им время и продлит паузу ровно на столько.

> Реально уходит до 6 заливок в час. Блокировка у Discord наступает при 10 000
> отклонённых запросов за 10 минут — разница в четыре порядка.

## Безопасность

> [!IMPORTANT]
> Репозиторий публичный вынужденно: аккаунт под торговыми ограничениями,
> приватные создавать нельзя. Поэтому важно, что именно в нём лежит.

**Чего здесь нет.** Токен бота, ID сервера, ссылка вебхука и пинг сторожа хранятся
в зашифрованных секретах GitHub. В коде их нет, в логи они не попадают, форкам
недоступны. История коммитов проверена — чисто.

<details>
<summary><b>Что сделано для защиты</b></summary>

<br>

- **Действия закреплены по хешу коммита**, а не по тегу. Тег можно переставить
  на другой код, хеш — нет. Это защита от подмены действия, у которого есть
  доступ к секретам.
- **Права прогонов урезаны** до `contents: read` — читать репозиторий и только.
  Исключение — продление расписания, ему нужна запись.
- **Dependabot** раз в месяц обновляет закреплённые хеши и зависимости, чтобы
  закрепление не превратилось в застой без исправлений безопасности.
- **Токен продления** тонкой настройки: ограничен одним репозиторием
  и четырьмя правами.

</details>

<details>
<summary><b>Что зависит от владельца</b></summary>

<br>

- Включить двухфакторную аутентификацию на GitHub и на cron-job.org —
  в обоих аккаунтах лежат ключи от бота.
- Не давать никому доступ к репозиторию: секреты видны любому,
  у кого есть право на запись.
- Если токен или вебхук где-то засветились — пересоздать. Вебхук в настройках
  канала, токен бота в Developer Portal, дальше обновить секрет в репозитории.
- Токены со сроком однажды перестанут работать молча. Сторож это заметит:
  пинги прекратятся, придёт письмо.

</details>

## Если понадобится перенести

`banner.js` умеет работать постоянным процессом — на своей машине или на сервере:

```bash
npm i -g pm2
pm2 start banner.js --name banner && pm2 save && pm2 startup
```

pm2 сам поднимет его после падения и после перезагрузки. Реакция быстрее:
опрос каждые 30 секунд вместо 10 минут. Минус — пока машина выключена,
цифры замирают.
