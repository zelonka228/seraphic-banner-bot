# Discord Stats Bot

Живые счётчики сервера двумя способами:

1. **Строки в списке каналов** (`index.js`) — голосовые каналы-заглушки, которые бот переименовывает.
2. **Плашки прямо на баннере сервера** (`banner.js`) — бот рисует картинку и перезаливает её как баннер.

Способы независимы, можно включить любой из них или оба сразу.

## 1. Создать бота

1. https://discord.com/developers/applications → **New Application**
2. Вкладка **Bot** → **Reset Token** → скопировать токен
3. Привилегированные интенты включать **не нужно**
4. Пригласить на сервер (подставь свой Client ID):
   `https://discord.com/oauth2/authorize?client_id=ТВОЙ_CLIENT_ID&scope=bot&permissions=48`

   `48` = «Управлять каналами» (для счётчиков-каналов) + «Управлять сервером» (для баннера).

## 2. Настроить

```bash
copy .env.example .env
```

В `.env` вписать токен и ID сервера (ПКМ по иконке сервера → «Копировать ID сервера»;
режим разработчика включается в Настройки → Расширенные).

```bash
npm install
```

## 3. Счётчики в списке каналов

```bash
npm run setup   # один раз: создаёт категорию и каналы, сам пишет их ID в config.json
npm start       # рабочий режим
```

Тексты меняются в `config.json` → `counters`, `{count}` — место для цифры.

## 4. Плашки на баннере

**Требуется 2-й уровень бустов сервера (7 бустов)** — без него Discord не даёт менять баннер.
Бот это проверяет и честно пишет в консоль, если уровня нет.

1. Положить свою картинку-подложку в `assets/banner-base.png` (лучше 960×540).
   Без файла рисуется тёмная заглушка.
2. Посмотреть результат, не трогая сервер:

```bash
npm run preview
```

Создаст `preview.png` с выдуманными цифрами — удобно подгонять позицию и цвета.

3. Запустить:

```bash
npm run banner
```

### Настройка внешнего вида — `config.json` → `banner`

| Поле | Что делает |
|---|---|
| `badges[].counter` | что показывать: `members`, `online`, `voice`, `boosts` |
| `badges[].icon` | иконка: `mic`, `users`, `boost` |
| `badges[].prefix` | текст перед числом, например `"Онлайн: "` |
| `badges[].locale` | `"none"` — `55335`, `"ru-RU"` — `55 335` |
| `style.x` / `style.y` | левый верхний угол первой плашки (холст 960×540) |
| `style.background` / `style.text` | цвет плашки и цвет цифр |
| `style.opacity` | прозрачность плашки, 0–1 |
| `style.scrim` | затемнение левой части картинки под плашками, 0–1 |

### Тестовая страница `preview.html`

Двойной клик по `preview.html` — откроется имитация Discord с твоим баннером
и живыми ползунками: положение, размер, цвета, набор счётчиков, тестовые цифры.
Внизу страницы — готовый блок JSON, который копируется прямо в `config.json`.

Если браузер не показал арт (некоторые сборки Chrome блокируют локальные файлы),
подними мини-сервер из папки проекта и открой http://localhost:4173/preview.html:

```bash
python -m http.server 4173
```

### Пресеты под светлый розовый баннер (Seraphic Aurora)

Белое стекло с малиновым текстом — стоит в `config.json` по умолчанию:

```json
{ "background": "#ffffff", "opacity": 0.86, "text": "#c2276f",
  "border": "#ee7fc6", "borderWidth": 3, "radius": 20,
  "shadow": 1, "shadowColor": "rgba(176, 31, 99, 0.32)" }
```

Розовая заливка с белым текстом — заметнее на светлых участках арта:

```json
{ "background": "#f06fc0", "opacity": 0.93, "text": "#ffffff",
  "border": "#ffffff", "borderWidth": 3, "radius": 20,
  "shadow": 1, "shadowColor": "rgba(150, 20, 90, 0.38)" }
```

Кириллица в `prefix` требует своего шрифта: положи любой `.ttf` в `assets/font.ttf`.
На Linux-хостинге файл шрифта обязателен — системных шрифтов там обычно нет.

## Хостинг 24/7 — GitHub Actions

Репозиторий: https://github.com/zelonka228/seraphic-banner-bot

Боту не нужен постоянно работающий сервер: он не слушает порты и не ждёт команд,
а раз в 10 минут просыпается, обновляет баннер и выключается. Именно так и устроено
расписание — файл `.github/workflows/banner.yml` запускает `once.js` каждые 10 минут.

Почему так, а не «бесплатный хостинг»:

- **Ничего не засыпает.** У бесплатных тарифов Render и подобных процесс усыпляют
  после простоя, и счётчики замирают. Здесь усыплять нечего.
- **Публичный репозиторий = безлимитные минуты.** GitHub Actions для публичных
  репозиториев бесплатен без ограничения по времени.
- **Само себя чинит.** Каждый запуск независим. Упавший прогон никак не мешает
  следующему — через 10 минут стартует чистый процесс. Поднимать вручную нечего.
- **Кулдаун соблюдается расписанием.** Интервал запуска совпадает с кулдауном
  заливки, так что превысить лимит Discord невозможно даже теоретически.

### Секреты репозитория

`Settings → Secrets and variables → Actions`:

| Секрет | Обязателен | Что это |
|---|---|---|
| `DISCORD_TOKEN` | да | токен бота |
| `GUILD_ID` | да | ID сервера |
| `ALERT_DISCORD_WEBHOOK` | нет | вебхук канала для оповещений о сбоях |
| `TELEGRAM_BOT_TOKEN` | нет | токен бота от @BotFather |
| `TELEGRAM_CHAT_ID` | нет | твой chat_id |

### Оповещения о сбоях

Настраивается любой канал или оба сразу. Если не настроен ни один, бот просто
пишет в лог и работает дальше — молча падать он не начнёт.

**Discord.** Настройки нужного канала → Интеграции → Вебхуки → Новый вебхук →
Копировать ссылку. Её в секрет `ALERT_DISCORD_WEBHOOK`. Лучше завести отдельный
закрытый канал для админов.

**Telegram.** Написать @BotFather команду `/newbot`, получить токен. Затем написать
своему боту любое сообщение и открыть
`https://api.telegram.org/bot<ТОКЕН>/getUpdates` — там будет `chat_id`.

Что приходит:

- бот не смог войти в Discord (токен отозван или протух);
- пропало право «Управлять сервером»;
- у сервера пропал уровень бустов для баннера;
- Discord принял заливку, но баннер не сменился;
- любое падение самого запуска — сборки, зависимостей, сети.
  Сообщение содержит ссылку на логи прогона.

Обычные ситуации — «цифры не изменились», «рано, кулдаун» — не оповещения,
они просто пишутся в лог прогона.

### Что стоит знать про расписание

- Запуски по `schedule` в GitHub Actions **не обязаны быть минута в минуту**.
  В часы пиковой нагрузки они опаздывают, иногда на 10–20 минут. Для счётчиков
  это некритично, но идеальной пунктуальности ждать не стоит.
- Если в репозитории **60 дней нет активности**, GitHub отключает расписание
  и присылает письмо. Достаточно раз в пару месяцев сделать любой коммит.
- Запустить обновление прямо сейчас: вкладка Actions → Баннер → Run workflow.
  Там же есть галочка холостого прогона — посчитает и нарисует, но не зальёт.

### Если хочется постоянного процесса

Вариант с расписанием предпочтительнее, но `banner.js` умеет работать и как
обычный демон — на своей машине или VPS:

```bash
npm i -g pm2
pm2 start banner.js --name stats-banner
pm2 save && pm2 startup
```

pm2 сам перезапустит процесс после падения или перезагрузки.

## Как часто обновляются цифры

Опрос и запись разведены — это разные по цене операции.

| Параметр в `config.json` | Что делает | По умолчанию | Минимум |
|---|---|---|---|
| `pollSeconds` | как часто бот смотрит статистику сервера | 30 с | 15 с |
| `renameCooldownMinutes` | не чаще этого переименовывается один канал | 6 мин | 5 мин |
| `banner.uploadCooldownMinutes` | не чаще этого перезаливается баннер | 10 мин | 5 мин |
| `banner.maxUploadsPerHour` | жёсткий потолок заливок за час | 6 | — |
| `voice.excludeBots` | не считать ботов, сидящих в войсе | да | — |
| `voice.excludeAfk` | не считать тех, кто ушёл в AFK-канал | да | — |

Опрос ничего не стоит: данные и так лежат в кэше клиента, запросов к Discord он не делает.
Поэтому изменение бот замечает за секунды и записывает его в первый же момент, когда
откроется окно записи. Если цифра не менялась — запрос не отправляется вообще, и лимит
копится про запас.

Ставить `renameCooldownMinutes` ниже 5 бессмысленно: Discord разрешает **2 переименования
канала за 10 минут**, то есть ровно одно в 5 минут. Код не даст поставить меньше.
По умолчанию стоит 6 — минута запаса, чтобы бот не работал впритык к лимиту.

Момент последней записи бот хранит в файле `.state.json` рядом с собой. Благодаря этому
перезапуск не обнуляет бюджет запросов: после рестарта бот помнит, что писал две минуты
назад, и дождётся своего окна вместо немедленной второй записи. Файл создаётся сам,
трогать его не нужно; удалишь — бот просто начнёт отсчёт заново.

### Четыре рубежа против лимитов

1. **Цифра не изменилась — запроса нет вообще.** Ночью бот часами молчит и копит бюджет.
2. **Кулдаун** — не чаще раза в 10 минут, жёстко зажат снизу пятью.
3. **Часовой потолок** — не более 6 заливок в скользящий час, независимо от всего остального.
   Считается по журналу в `.state.json`, переживает перезапуск.
4. **Сигнал самого Discord.** Если он придержит запрос, бот прочитает названное им время
   и продлит паузу ровно на столько — вместо угадывания. Записывается на диск,
   так что перезапуск паузу не сбросит.

После каждой заливки бот сверяет хеш баннера до и после: если Discord принял запрос,
но картинка не сменилась, в консоли будет отметка об этом.

### Про блокировки

Ответ 429 — это не бан и не санкция, а штатное «подожди»: библиотека сама повторит запрос.
Настоящая блокировка по документации Discord наступает при **10 000 отклонённых запросов
за 10 минут** — тогда Cloudflare закрывает доступ к API на час. Этот бот делает порядка
12 записей в час, то есть на четыре порядка меньше порога. Ставить интервалы пореже
«для безопасности» смысла нет — на риск блокировки это не влияет, только замедляет цифры.

Лимит на заливку баннера Discord не публикует. На 10 минутах он ведёт себя стабильно,
5 минут — нижняя граница, которую код принимает. Если поймаешь 429, бот сам удвоит паузу
для этой цели и напишет об этом в консоль, а не будет долбиться дальше.

## Подводные камни

- `online` берётся через `withCounts` — приблизительное значение от Discord,
  зато без привилегированного интента Presences.
- Баннер в списке каналов Discord обрезает по краям — держи плашки подальше от границ.
